Foundation

先理解：智能体由什么构成

智能体（Agent）是能「感知环境、自主决策、执行行动」的程序。它是大模型的「大脑 + 手脚 + 记忆 + 工具」。

👁️

感知层 Perception

通过多模态接口获取信息：视觉识别图像缺陷、语音理解情绪、API 读取金融行情与传感器数据。

🧠

规划层 Planning

灵魂所在。把「写一篇深度报告并发布」拆成大纲、查资料、撰写、格式化等子任务，再逐项执行。

🗂️

记忆层 Memory

短期记忆是上下文窗口；长期记忆通过 RAG 与向量数据库沉淀行业知识，解决模型知识更新慢的问题。

🛠️

工具层 Tools

调用 API、执行代码、操作浏览器。让智能体从「只会说」变成「能干活」，真正影响现实世界。

Prompt Engineering 基础

提示词工程 · 最底层的「问话艺术」
▼

通过精心设计输入给大模型的指令，让模型更稳定地产出期望结果。这是 Agent 时代的起点，也是所有人最先接触的一层。

关键方法

  • 结构化提示：用 CO-STAR 等框架组织角色、目标、风格、受众等要素
  • Few-shot 示例：在提示中给出输入-输出样例，引导模型模仿
  • 思维链（Chain-of-Thought）：要求模型先推理再作答，提升复杂问题正确率
它的局限：只优化「一句话」。当任务变复杂，单靠提示词无法让模型稳定地查资料、跑代码、自我纠错——这正是上层工程范式出现的原因。
🧩

Context Engineering 基础

上下文工程 · 决定模型「看到什么」
▼

管理「喂给模型的上下文」的工程：哪些信息进、哪些不进、以什么顺序与格式组织，直接决定模型回答质量。上下文是 Agent 的「工作台」，放什么决定它能干成什么。

核心手段

  • 上下文窗口管理：长期任务中裁剪、摘要、压缩历史，防止目标被淹没
  • RAG 注入：检索相关知识后拼入上下文（见 RAG 概念）
  • 分层提示词：身份、工具定义、安全策略等固定内容与任务动态内容分层组织
🔄

Agent Loop（ReAct）基础

智能体循环 · Agent 的「心跳」
▼

2022 年提出的 ReAct（Reason + Act）框架，让模型进入「想一步、做一步、看结果」的循环，是所有智能体的最小工作单元：

  • 思考 Thought：分析当前情况，决定下一步
  • 行动 Action：调用工具——查资料、跑代码、搜网页
  • 观察 Observation：看工具返回结果，回到思考
类比：像一名实习生，老板给目标，他自己琢磨、动手、看反馈，错了再改直到交差。灵活，但出问题不好追溯、中途崩溃难以续跑。
🐎

Harness Engineering 工程范式重点

驾驭工程 · Agent 的「操作系统」
▼

Harness 直译为「马具、缰绳」。大模型是匹千里马，Harness 是驾驭它的全套装备。核心公式：Agent = Model + Harness——模型决定「多聪明」，Harness 决定「能不能稳定把活干完」。

起源与走红

  • 2026 年 2 月：HashiCorp 联合创始人 Mitchell Hashimoto 在个人博客首次提出 harness engineering，指「每当发现 AI 智能体犯错，就设计解决方案防止再犯」
  • 2026 年 2 月：OpenAI 发文跟进推广
  • 2026 年 8 月：DeepSeek 开源 DeepSeek Harness，国内多家厂商接入，概念彻底出圈

Harness 包含什么

  • 系统提示词与工具说明（决定模型行为边界）
  • 记忆与状态管理（让 Agent 拥有长期记忆）
  • 任务拆分与重试机制（长任务可靠执行）
  • 权限控制、审计追踪与评测体系（企业级治理）

参考：Claude Code 的六大核心组件

Anthropic 的 Claude Code 源码（约 51 万行）泄露后，业界分析出其 Harness 六大组件：

组件作用
多层级 System Prompt身份、工具、安全策略，可达十几万 token
Tool Schema（工具规范）工具定义直接决定调用准确率
Tool Call Loop先规划后执行，降低长链路中间错误
Context Manager指针式记忆，解决百万 token 上下文利用
Sub Agent（子智能体）共享 KV Cache，成本远低于串行执行
Verification Hooks防止模型「自我美化、虚报完成」

Harness vs Framework

  • Framework（框架）解决「如何开发一个 Agent」——像招聘手册
  • Harness解决「如何让一个 Agent 长期可靠地运行」——像企业管理系统
动手起点：最小可用的 Harness 只需约 200 行——在项目根目录写一个 AGENTS.md，定义「项目说明、禁止操作、完成定义」，Agent 启动时自动读取。OpenAI 团队曾用不到 100 行的 AGENTS.md 让 Codex 稳定写出超 100 万行代码。
🛰️

Loop Engineering 工程范式

循环工程 · 给 Agent 装「自动巡航」
▼

2026 年上半年走红的概念。核心思想（Google 前工程师 Addy Osmani）：「不再由你亲自提示 AI，而是设计一个系统让系统代替你提示 AI」。人从「操作员」变成「定目标和验收标准的人」。

LangChain 总结的循环四层级

层级含义
基础循环模型循环调用工具直到完成
验证循环输出不达标就带反馈重试
事件驱动循环由定时任务或消息触发自动运行
爬山循环分析运行记录，自动改进提示词与工具配置
局限：一个循环里所有事情挤在一起，上下文容易「腐烂」；出错时常常要整段重来。这正是 Graph Engineering 要解决的问题。
🕸️

Graph Engineering 工程范式重点

图工程 · 从「单兵作战」到「开公司」
▼

2026 年 7 月被推到台前的范式：把 AI 系统画成一张「执行图」来设计和运行——把多个智能体、普通代码、验证器、人工审批组织成一张「看得见、管得住、坏了能修」的图。它不是给人看的示意图，而是给机器跑的真实系统。

四个基本要素：G = (V, E, S, P)

要素含义
节点 V干活的单元：代码、模型调用、带工具的智能体、验证器、人工审批
边 E路由：顺序、条件分支、并行分发、结果汇合、循环重试
状态 S沿边流动的共享数据：进度、证据、预算、中间产物、检查点
策略 P权限规则：谁能建节点、调工具、改图、产生副作用

它解决单 Agent 循环的六大硬伤

问题图的解法
上下文腐烂拆成独立节点，隔离上下文
错误级联拆出独立验证节点专门挑错
工具过载按职责分工，每个节点管好自己的工具
缺乏控制粒度通过节点和边灵活控制，随时插队
可观测性差图结构清晰，每条路径都可追溯
目标失明「判断」与「验证」分离

核心武器：验证器（Verifier）

把「出结论」和「检查结论」拆成两个节点：一个智能体产出结论，另一个用全新上下文专门试图推翻它。扛得住才放行，扛不住打回重做——避免「既当运动员又当裁判」。

两个常见误解

  • 图工程 ≠ 知识图谱：知识图谱描述「实体之间的关系」（GraphRAG 那种）；图工程是控制图，描述「系统下一步运行谁」
  • 图工程 ≠ LangGraph：LangGraph 只是实现图工程的一个流行框架，普通 Python、Airflow 等同样可以实现
适用判断：任务短、路径固定、单目标、停止条件明确 → 别画图；任务长、要并行、要质检、要审批、要恢复 → 才值得把流程画成图。LangChain 官方也指出：过度画图会压缩智能体的探索空间。

RAG 检索增强生成 关键组件

给 AI 戴上的「行业参考书」
▼

Retrieval-Augmented Generation：先生成问题的向量表示，从向量数据库检索相关知识片段，与用户问题拼在一起再交给模型生成答案。解决大模型知识更新慢、易幻觉的问题。

核心环节

  • 文档切分与向量化：把知识库切成块，用 Embedding 模型转成向量
  • 向量检索：用向量数据库（Chroma / Pinecone / Milvus 等）做相似度召回
  • 生成：检索结果 + 问题 → 大模型 → 带来源的答案
进阶玩法 GraphRAG：用知识图谱组织实体关系后再检索，能回答「关于整个语料库」的全局性问题，而非单一片段。
🤝

Multi-Agent 多智能体协作 工程范式

从单智能体到「群体智能」
▼

让多个专业化的智能体分工协作：程序员 Agent 写代码、测试员 Agent 找 Bug，互相配合完成任务。常见模式：主管-工人（主智能体规划、子智能体并行执行）、流水线（角色按顺序接力）、辩论/对抗（多角色互相质疑）。

典型效果

  • Anthropic 多智能体研究系统采用「主管-工人」模式，比单智能体方案性能提升约 90%（第三方评测数据）
  • Uber 用子图给不同语言、不同仓库分配专门子智能体，配合检查点扛住 CI 中断，节省超 2 万工程小时
关键挑战：智能体之间的通信协议、任务分配、冲突消解、结果聚合与治理——这正是 Graph Engineering 的组织维度。
🔌

MCP 与工具调用 关键组件

智能体的「手脚插槽」
▼

工具调用（Tool Use / Function Calling）让模型能「动手」：读文件、执行命令、调 API、查数据库。MCP（Model Context Protocol，模型上下文协议）是 Anthropic 推动的开放标准，把工具、资源、提示统一成可插拔接口——像给 AI 装 USB 接口，一套协议接遍各种工具。

为什么重要

  • 工具定义的质量直接决定调用准确率（Harness 中 Tool Schema 的重要性）
  • 避免「一个 AI 挂太多工具」导致的准确率暴跌——按职责分工（Graph 的解法）
  • OpenAI Agents SDK、DeepSeek Harness 等已把 memory、sandbox、文件系统、MCP 等纳入标准化 Harness
📊

Agent 评估与可观测性 关键组件

不评估，就不知道 Agent 靠不靠谱
▼

生产级 Agent 必须回答：完成率多少？在非预期输入下健壮吗？每一步为什么这么走？

评估维度

  • 任务完成率：端到端是否交付正确结果
  • 基准评测：如 Terminal Bench 等真实任务基准（Harness 优化曾把同一模型的得分从 52.8% 提到 66.5%，模型未变、只改工程）
  • 可观测性：图结构下每条路径可追溯；验证钩子防止「虚报完成」
  • 成本与延迟：好的 Harness 可把单次任务成本降低约一个数量级
评估是 Agent 工程的「仪表盘」：没有评测体系，Harness 优化就是盲人摸象。
没有匹配的概念，换个关键词试试。

Relations

三个范式的层级关系

不是「谁取代谁」，而是一层套一层——Graph 里每个节点藏着 Loop，Loop 里跑着最基本的 Agent 循环。

GRAPH ENGINEERING · 图工程 = 开一家公司
LOOP ENGINEERING · 循环工程 = 自动巡航
Agent Loop · 智能体循环 = 一个员工「想-做-看」 思考 → 行动 → 观察 → 再思考…

一句话记住：Agent 循环是「动作」，Loop 工程是「让动作自动循环的系统」，Graph 工程是「把多个循环和节点组织成一张图」。LangChain 官方也直言：循环就是图的一种简单形式（有向循环图）。

Roadmap

学习路线：从 L0 到 L3

一条兼顾「低代码上手」与「深度工程」的进阶路径。每层都有明确的必做项与验收标准。

🌱
L0 觉醒级 约 1–2 周

建立正确认知

适合：所有人 / 零基础小白
  • 理解「概率预测 ≠ 事实检索」：大模型会一本正经地胡说（幻觉）
  • 了解智能体四大模块：感知、规划、记忆、工具
  • 认识 Agent Loop：思考-行动-观察的最小循环
  • 在低代码平台（扣子 Coze / Dify）搭建第一个智能体
验收标准：能搭建一个日程规划助手——输入模糊文字，准确提取时间、事件并同步到日历。
🛠️
L1 工匠级 约 3–6 周

给 AI「接上手脚」

适合：开发者 / 想深入的技术爱好者
  • 掌握 Python 基础 + 调用大模型 API（OpenAI / DeepSeek / 通义等）
  • 学会结构化提示词与函数调用（Function Calling）
  • 用 API 串联两个不相关系统（如把知乎热榜自动转成文档）
  • 入门 RAG：文档切分、向量化、检索、生成
验收标准：你的工作流包含至少 3 个判断分支；能基于自有文档做问答。
🏗️
L2 架构级 约 2–3 个月

解决「智商波动」与「胡言乱语」

适合：后端工程师 / 架构师 / 准智能体工程师
  • 掌握向量数据库（Chroma / Pinecone / Milvus）与 RAG 优化
  • 用 LangGraph / AutoGen 等框架实现多节点工作流
  • 设计记忆与状态管理（短期 / 长期记忆、检查点）
  • 理解 Loop Engineering：验证循环、事件驱动循环
  • 搭建 Agent 评测：任务完成率、成本、可观测性
验收标准：Agent 处理 10 万字文档时检索准确率稳定达标；长任务可中断续跑。
🚀
L3 专家级 持续进阶

设计 Harness 与 Graph 系统

适合：智能体架构师 / Harness 工程师 / 技术负责人
  • 为项目编写 AGENTS.md / CLAUDE.md，定义行为纲领与完成标准
  • 设计多智能体图：节点、边、状态、策略（G = V, E, S, P）
  • 实现独立验证器节点，把「判断」与「验证」分离
  • 搭建权限控制、审计追踪、安全沙箱（企业级治理）
  • 参与开源（DeepSeek Harness、OpenClaw、LangGraph 等）并沉淀方法论
验收标准：你的 Agent 系统能端到端交付真实任务，出错可追溯、可恢复、成本可控。

FAQ

常见问题

学智能体必须学 Python 吗？▼
分情况：只做业务应用，低代码平台（扣子 Coze、Dify）已经足够；想做深度定制、私有化部署或 Harness/Graph 工程，Python 仍是金钥匙——几乎所有主流框架都基于 Python。
需要买昂贵的显卡吗？▼
初期完全不需要。直接使用云端大模型 API 或厂商免费额度即可；本地部署（如 Ollama + Dify）可以后面再考虑。
智能体和传统自动化（RPA）有什么区别？▼
RPA 是死板的规则执行，流程写死；Agent 具备根据环境变化调整策略的能力，能处理非预期输入，更适合开放任务。
为什么我的 Agent 经常「不听话」？▼
通常是提示词不够结构化（试试 CO-STAR 框架），或缺少验证/反思节点。更进一步，需要 Harness 层的约束——把「禁止操作」「完成定义」写清楚，用验证器兜底。
图工程是不是越复杂越好？▼
不是。任务短、路径固定、停止条件明确时画图反而压缩智能体的探索空间。只有当任务长、要并行、要质检、要审批、要恢复时，图的价值才体现出来。先找最简单的方案。
Harness、Loop、Graph 到底先学哪个？▼
建议按这条线：先吃透 Agent Loop（ReAct）——一切的地基；再理解 Loop Engineering 的循环思维；然后掌握 Harness 的「约束与治理」思想；最后用 Graph 组织多智能体系统。层层递进，不需要一上来就啃最复杂的。
如何评价一个智能体的好坏？▼
看两点：处理非预期输入时的健壮性，以及最终任务完成率。再配合成本、延迟、可观测性三个指标综合评估——这也是 Harness 中评测体系要解决的。
